# V1-V38 全版本演进与交付总说明

## 总体演进

这套系统从 V1 到 V38 的核心变化，是从“让两个 agent 互相挑刺写论文”逐步升级为“真实数据驱动的建模路线探索与证据门槛裁判”。早期版本更像工作流设计；中期开始接入 benchmark、adapter 和 baseline；后期重点转向可复现、可交接、可审计。

## 阶段摘要

| 阶段 | 重点 | 结果 |
| --- | --- | --- |
| V1–V8 | 对抗 agent 雏形 | 明确建模方、评审方、终审方的基本闭环，但代码与数据证据不足。 |
| V9–V18 | C 题实践试跑 | 用 2025 C 题样例验证流程，发现“论文能写好但模型证据不够硬”。 |
| V19–V25 | 架构泛化 | 从单题专攻改为多题型路线探索，强调不同建模路径对比。 |
| V26–V28 | benchmark 雏形 | 增加评价类、优化类、预测类基准任务。 |
| V29–V33 | 证据门槛 | 引入 baseline 对比、路线淘汰、limitations 审计。 |
| V34–V36 | 真实资料适配 | 接入机制/空间/C题专向历史数据 adapter。 |
| V37 | 自包含交接包 | 把最小原始数据子集打入包内，开始支持解压复现。 |
| V38 | 显式角色严格门槛 | 修复角色猜测、虚假指标、自预测泄漏、旧入口混乱等关键缺陷。 |

## V38 当前定位

V38 是一个 Codex skill 风格的自包含交接包，能力边界如下：

- 能做：在已有真实数据 adapter 上比较路线、检查 baseline、产出模型推荐证据；
- 能做：给新赛题提供建模路线探索框架和代码接口；
- 不能直接保证：不补 adapter 的情况下自动解决任何新题；
- 不应宣称：一键生成国一等奖论文。

## V38 修复重点

- 主入口统一为 `tools/run.py`；
- 旧 `orchestrator.py`、旧 patch 脚本、旧 V29/V31/V33/V37 运行入口不再作为 runtime 交付；
- 数据根默认改为包内 `data/reference_root`；
- 2012A 旧虚假 wrapper 移除，避免默认 `1.0` 指标污染；
- 2012A 自预测路线 `second_panel_baseline` 移除；
- `route_contract` 显式声明路线角色，禁止按名称猜 baseline；
- 完整路线缺主指标时 hard fail；
- 增加负向测试保证问题不会悄悄回归。

## 内置数据口径

V38 包内已包含自包含复现数据，路径统一写为：

```text
data/reference_root
```

历史开发阶段曾使用外部资料盘，但 V38 交接包不要求队友具备这些外部路径。

## 交接建议

队友拿到包后，先读 `SKILL.md`，再运行 `README_REPRODUCE.md` 中的一键复现命令。若要迁移到新赛题，优先新增 adapter 和 baseline，再接入 `ROUTE_CONTRACT`，最后让 `v38_explicit_role_gate.py` 审计。
